# CS-255-System-Analysis-and-Design--Business-Requirements-and-System-Design
These documents were created for the DriverPass client where they seek to create a web-based program that will provide a better driver training for customers.

The DriverPass project was made for the owner of DriverPass which is a business that caters to helping people pass their driving exam.
DriverPass wishes to create a web-based application that will provide online practice exams and on-the-road training which will better
prepare customers to pass their driving exam. The client requested that the system allows customer to purchase from three different 
driving training packages, have the ability to schedule a 2-hour driving lesson, view their driving notes online provided by their driving
instructor, take practice exams and track their progress. For this project, I was most efficient in making sure all the requirements of the
client was met by translating their needs into technical solutions as shown in both the documents. 
If I had to choose one part of my work to revise, I would choose to revise the "Assumptions" section located in the Business Requirements
document. I would improve this section by removing a few of the previously added assumptions such as "It is assumed that the DMV will provide a useable format of their updated rules, policies and practice test information that can be used by the DriverPass system." I 
interpreted the various needs of the users into the system design by first having a clear understanding of what the users want the system
to do then translating that in a technical design. For example, a need of the system was for the system to allow the owner to view and
download an activity record and work with it offline. I translated this by implementing a role-based authorization feature so that only 
the authorized users (the owner and IT officer) will have access to that data. If the needs of the users are not considered when 
designing a program, then you will eventually create a program that does not solve the problem of the user or meet the requirements of
the client. 
My approach to designing software would be to first gather the client requirements so I can have a clear understanding of what the 
client needs the system to do and what features should be implemented to help solve the various problems that the client may have. I would then implement various diagrams such as the UML sequence, activity and class diagrams to help me outline what needs to be implemented
and how each part of the system will be dependent and related to each other. Lastly, I will also use a Gnatt chart to help me create a 
timeline of the different tasks and to help track the progress of this project.
